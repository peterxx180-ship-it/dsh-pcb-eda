# 局部电路的连线与验收

目标：读者能沿导线看懂一个局部电路，不需寻找每个器件两端的同名标签。先读取本页，再选实际拓扑匹配的画法说明、代码和图片；没有读过的参考不能视为已采用。

## 局部连接和边界信号

在放置前列出两类设计意图；它们不是新的 addComponent 参数：

- `localConnections`：本单元内应直接相连的引脚对，如 VIN–Cin、VOUT–Cout、CC1–下拉电阻、输入座–保护器件、MCU–串联电阻–接口。多器件串联拆成相邻引脚对，不跨器件内部声明一条导线。
- `boundaryPorts`：已完成局部单元的输入、输出或跨区/跨页信号。通过短线、端口和标签连接；供电/地符号可保留。已有 ports 返回值可直接承担这一角色，无需重复造字段。

标签给完整电路命名，不替代同框内邻近外围的导线。两器件同网不代表局部画法已经合格。远端测试点、独立接口、DNP 和供电引用等确需单独表示时明确说明，不用“禁止全部标签”或固定线长/连线比例衡量美观。

每个新增或重画模块在编码前按实际 reference/pin 列出主通路及所属外围的相邻连接，汇总为检查清单；不能仅挑已经画好的一条支路证明整图合格。模块无局部连接时说明其确为独立接口等原因；例外记录具体端点及理由，不靠清空清单通过。复用且未改内部电路的模块保留已确认布局，检查改动部分。

| 电路 | 应直接绘制的关系 | 适合标签的位置 |
| --- | --- | --- |
| LDO | 输入电容–VIN、输出电容–VOUT、地回路 | 完整单元的输入/输出母线 |
| USB-C | CC1/CC2–各自下拉、串阻/ESD 所属信号 | 跨区 D+/D−、VBUS 边界 |
| 电源入口 | 电池座–保险/防反接–保护节点–输入电容 | 电源分配出口 |
| 复位/启动 | 上拉–复位节点–按键/电容 | EN/BOOT 接往主控的位置 |
| BUCK/BOOST | SW–电感/二极管、自举、反馈分压、所属电容 | 完整电源输出、远端使能 |
| 接口/驱动 | 芯片–串阻/驱动级–本地接头 | 跨功能区信号 |
| 充电管理 | 输入保护链–VIN、BAT–本地电池接口、PROG–设定电阻、所属输入/输出电容 | 充电输入边界、电池电源分配、远端状态信号 |
| MCU/传感器 | 晶振脚–晶振–负载电容、专用 DEC 脚–对应电容、复位脚–本地复位网络、供电脚–所属去耦支路 | 已完成局部电路的调试、通信和跨区信号 |
| I²C 电平转换 | 两侧 SDA/SCL–各自上拉节点、VREF/EN–已确认偏置外围 | 接往远端主控/传感器的总线边界 |
| 射频匹配 | 本地输入–串联匹配–输出/天线、并联匹配支路接实际节点 | 独立射频区的输入边界；DNP 元件也保留拓扑位置 |

## 放置与绘制

先按电路路径选择器件方向，让需要相连的脚相向；外围靠所属引脚，主通路保持连续。先摆关键芯片/连接器，再摆外围，最后画短正交路径、分支点和属性。不能直接给所有脚套 lead()+label()。region 返回对象用于实际绘图，框不能替代电路组织。

放置 helper 返回真实引脚/角色，不自动给每个脚命名。两端无源器件由所属电路连接；IC 先分出内部布线脚、边界脚、电源和 NC，再仅向边界脚调用 attachPinLabels。使用 addComponent 时内部布线脚声明 manual。器件主通路优先左到右，供电在上、地向下；以真实引脚和合理短线为准，不为统一方向绕远。共享电源符号可跨区引用，但不能让它替代 LDO–Cin/Cout 或专用去耦脚–电容等本地关系。

使用现有 symbolOrientation、region.pin 和相同坐标系的辅助。需要四方向短引出时用 attachPinLabel，且只用于边界，不重写只支持左右却接收 up/down 的函数。固定引脚顺序有碍布线时，先旋转或调整相邻器件；不为排版随意更改真实脚号或临时重造芯片符号。

读图从局部主通路开始，再看文字。器件本体很小而大段说明占满框时，把长解释放回方案，保留必要条件和警告，再收紧外框。模块间连线过密或页面难以阅读时选择合理多页，不能一味扩大纸张，也不把所有跨区线强行直连。

## 两层检查

connect 完成后，用内置报告核对计划中的局部引脚对：

```js
const local = sch.localConnectionsReport([
  { name: 'VIN 到输入电容',
    from: {reference: refs.ldo, pin: pins.vin},
    to: {reference: refs.cin, pin: capPins.top} },
]);
if (local.failed) throw new Error(JSON.stringify(local));
// 范例返回 localConnections 时，可合并所有单元的该数组后统一检查。
```

主入口检查所有受影响模块的计划清单已汇总，再执行报告；报告 failed 非零时抛错，不能只 console.error 后继续 save/发布。检查某类简单支路不能代表其他功能模块的局部电路已验收。清单覆盖核对属于设计审查，报告本身只验证传入的引脚对，不会发现漏报的意图。

scope=wire-geometry-only：只沿明确相接的导线端点检查，不沿标签、电源名称或器件内部穿越；未拆分的中途分支不能充当已确认通路。missing path 先修实际局部连线或明确例外，不为通过检查删除意图。报告聚合缺失脚号并优先返回失败项，最多40项，完整数量见 total/failed/truncated。

之后导出实际 KiCad 网表，按方案检查关键引脚应同网、应隔离、应明确未用；纯布局修改核对连接未变。几何通路通过不等于网表/电气正确，网表同网也不等于布局合格。不从刚生成的网表反推一份“预期表”再证明自己正确。

验收同时满足：局部路径连续可追踪、外围与所属脚直接相连、无无理由的标签小岛、属性可读、方向合理；再完成关键网表检查。仅外框无重叠或标签都存在不能交付为已检查完成。
